# M4b: the `mlx-lm-go` binary

> **For agentic workers:** implement task by task with red/green TDD. For every test: write it, run it, see it fail for the stated reason, then write the smallest code that passes. Steps use checkbox (`- [ ]`) syntax.

**Goal:** one binary, `mlx-lm-go`, that serves a real model over HTTP with the same answers as Python `mlx_lm.server`, plus a one-shot `generate` command.

**Architecture:** `cmd/mlx-lm-go` only wires packages that already exist and are tested: `internal/hub`, `internal/tokenizer`, `internal/chattemplate`, `internal/generate`, `internal/server`, `internal/webui`. Two small adapters make the tokenizer and template satisfy the interfaces `internal/server` defines. The command logic lives in functions that take arguments and writers, so tests call them without spawning a process.

**Tech stack:** Go 1.27 standard library (`net/http`, `os/signal`, `log/slog`, `flag`).

---

## Starting point

Read the exported API of each package above before writing anything. Recorded reference answers are in `testdata/server/*.json`; with temperature 0 the real engine must reproduce their text exactly.

## Files you own

Create: `cmd/mlx-lm-go/{main,run,server,generate,version,adapters}.go` and `_test.go` files.
Do not change other packages. If one of them lacks something you need, stop and report it.

## Contract

```
mlx-lm-go server   <the flags internal/server.ParseFlags accepts>
mlx-lm-go generate --model <dir or repo id> --prompt <text> [--system <text>] [--max-tokens N] [--temp T] [--chat-template-args <json>]
mlx-lm-go version
```

```go
// run executes one command line and returns the process exit code.
// ctx cancellation shuts a running server down.
func run(ctx context.Context, args []string, stdout, stderr io.Writer) int
```

- Exit codes: 0 success, 1 runtime failure, 2 usage error (unknown command, bad or unsupported flag). Usage errors print the reason and a one-line hint to stderr.
- `server` resolves the model with `hub.Resolve`, loads tokenizer, template (or the `--chat-template` override) and engine, then listens on `--host:--port`. Port 0 picks a free port. It prints `listening on http://<host>:<port>` to stderr once ready, and a warning when the host is not loopback. The embedded UI is always served.
- `server` shuts down when ctx ends: stop accepting, cancel in-flight generations, close the engine, return 0. `main` connects SIGINT and SIGTERM to that context.
- `generate` renders the chat template with an optional system message, streams the decoded text to stdout as it is produced, ends with a newline, and prints prompt tokens, generated tokens and tokens per second to stderr.
- `version` prints `mlx-lm-go <version> (MLX <mlx.Version()>, UI <webui.Version()>)`. The version is a package variable defaulting to `dev`, set at build time with `-ldflags`.

## Tasks

Run tests with `go test ./cmd/mlx-lm-go/ -run <Name> -v`. Tests that need the model call `hub.Resolve("mlx-community/Qwen2.5-1.5B-Instruct-4bit")` and skip when it fails; on this machine it resolves, so none may be skipped here. Load the model once per test binary and share it.

### Task 1: command dispatch

- [ ] No arguments, an unknown command, and `server` with an unsupported flag each return 2 and explain themselves on stderr.
- [ ] `version` returns 0 and prints a line matching `^mlx-lm-go \S+ \(MLX \d+\.\d+\.\d+, UI \S+\)$`.

### Task 2: generate

- [ ] `generate --model <qwen2.5> --prompt "Count from 1 to 5." --max-tokens 24` writes exactly `1, 2, 3, 4, 5\n` to stdout and returns 0.
- [ ] `--system "You are a terse assistant." --prompt "What is the capital of France?"` writes `Paris.\n`.
- [ ] A model that is not cached returns 1 and the message contains `hf download`.

### Task 3: serve a real model

Start `run` with `server --model <qwen2.5> --port 0` in a goroutine, read the listening address from stderr, and use a real HTTP client.

- [ ] `POST /v1/chat/completions` with the request of `testdata/server/chat.json`: the content, `finish_reason`, `usage.prompt_tokens` and `usage.completion_tokens` equal the recording's (`"1, 2, 3, 4, 5"`, `"stop"`, 37, 14).
- [ ] The streamed variant (`chat_stream.json`): the joined `delta.content` equals the same text and the stream ends with `[DONE]`.
- [ ] `chat_length.json`, `chat_stop_string.json`, `chat_stop_single.json`, `chat_content_parts.json`, `completions.json`: content or text and `finish_reason` equal each recording's.
- [ ] `GET /` returns the embedded UI; `GET /v1/models` lists the `--model` value.
- [ ] Cancelling ctx during a long generation (`max_tokens` 2000 on "Write a long story.") makes `run` return 0 within five seconds, and the client sees its stream end.
- [ ] Two servers on the same port: the second returns 1 with an error naming the address.

### Task 4: template override

- [ ] `--chat-template '{{ messages[0].content }}'` makes the engine receive exactly the encoded user text. Assert through the response's `usage.prompt_tokens` equalling the token count of that text.

### Task 5: client conformance against the real engine

- [ ] With `MLX_LM_GO_PYTHON` set, run `tools/conformance/openai_client.py` against the running server and require exit 0. Skip when the variable is unset. On this machine run it with `MLX_LM_GO_PYTHON=/Users/b33j_02/sandbox/mlx/.venv/bin/python`.

### Task 6: build

- [ ] `make build` produces `bin/mlx-lm-go`; `./bin/mlx-lm-go version` prints the version line. This is the one place you run a repository-level build.
