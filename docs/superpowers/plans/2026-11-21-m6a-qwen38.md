# M6a: Dense Qwen3.8 text inference implementation plan

> **For agentic workers:** use subagent-driven development. Write each behavioral test first, observe the expected RED, then implement and observe GREEN. Keep the failing and passing command/output in the handoff. A syntax error, skipped fixture, or unavailable checkpoint is not a behavioral RED. Use the selective commit tool for commits. Do not push or change fleet slots.

**Goal:** run dense Qwen3.8-27B and Qwen3.5-9B from pinned Hugging Face MLX snapshots through `mlx-lm-go generate` and the text HTTP API.

**Architecture:** use the existing model registry, locked inference thread, shared loader/quantized linear layers and MLX array scopes. Keep a depthwise convolution tail and recurrent state per Gated DeltaNet layer, and a normal growing KV cache per full-attention layer. The existing tokenizer, template, sampler and security middleware remain the only implementations of their respective contracts.

**Tech stack:** Go 1.27, mlx-c 0.8.0, MLX 0.32.4, Python `mlx-lm` 0.32.2 as the oracle only.

## Scope and decisions

- Flagship: [`mlx-community/Qwen3.8-27B-4bit@10c35caafbb80f7dc6a7a432cdd11af10a6d4818`](https://huggingface.co/mlx-community/Qwen3.8-27B-4bit/tree/10c35caafbb80f7dc6a7a432cdd11af10a6d4818). Small parity/interactive checkpoint: [`mlx-community/Qwen3.5-9B-MLX-4bit@938d8919941c6e7efd3c7150eff7fe9d12afa631`](https://huggingface.co/mlx-community/Qwen3.5-9B-MLX-4bit/tree/938d8919941c6e7efd3c7150eff7fe9d12afa631). Both use `model_type=qwen3_5`, `text_config.model_type=qwen3_5_text`, and affine 4-bit, group size 64. Qwen3.8’s stock checkpoint at `b935172e4bb5dcd0543774a34748fb92422e3027` has the same three weight blob hashes, but use the pinned snapshot for fixture regeneration (incl. template).
- Qwen3.8 is the quality target; Qwen3.5-9B is the quick path. Both previously ran offline with Python on the M4 Pro. No inference checkpoint is implicitly selected and no download is performed by the server. The older Qwen2 path must not change behavior.
- Match Python's text semantics: exact render and tokenization, per-request isolated state, and assistant `reasoning` separated from `content` on chat; text completions remain plain text. An image or video input is rejected, and incidental vision tower or MTP weights do not enter the text graph. No `qwen3_5_moe`, vision tower, MTP inference, prefix reuse, tools, logprobs, site changes, or live deployment in this task plan. M6b owns cache/tools/fleet requirements.
- Authoritative Python sources are `mlx_lm/models/{qwen3_5,qwen3_next,gated_delta,base,cache}.py`, `mlx_lm/utils.py` and `mlx_lm/server.py` under `/opt/homebrew/opt/mlx-lm/libexec/lib/python3.15/site-packages/`. Compare text behavior against the installed revision, not a newer online README or local third-party fork.
- Pinned tensor/metadata probes: both convolution tensors already use MLX `[channels,4,1]`. `A_log` is BF16 in Qwen3.8 and FP32 in Qwen3.5; Python casts either to FP32 before `exp`. Both have exact `<think>`/`</think>` added tokens (IDs 248068/248069) even though their `special` bit is false. Python stops on IDs 248044 and 248046 for Qwen3.8, but only the tokenizer fallback 248046 for Qwen3.5; do not import nested `text_config.eos_token_id` into the latter's effective stop set.

## A. Gated DeltaNet and narrow mlx-c ops

- [ ] Write behavioral tests in `mlx/ops_delta_test.go`: depthwise convolution preserves channels and shape; the fused recurrence matches deterministic Python 0.32.2 BF16 output and FP32 state with multiple value heads per key head, both with an empty state and continuation. Use K=32 or 128, not a tiny unsupported head size. Run `go test ./mlx -count=1 -run 'Test(DepthwiseConv1D|GatedDeltaUpdate)' -v` and record RED before binding.
- [ ] Bind grouped `mlx_conv1d` directly. Use `mlx` scope tracking for each returned array and release temporary C handles. Compute `beta = sigmoid(b)` and `g = exp(-exp(A_log.float32) * softplus(a + dt_bias))` in the reference dtype/order. Keep recurrent state FP32 and do not repeat grouped heads in Go.
- [ ] Use the upstream mlx-lm 0.32.2 unmasked scalar-gate Metal recurrence via `mlx_fast_metal_kernel` for the production shapes (retain the upstream attribution if adapting its source). The C built-in `mlx_fast_gated_delta_update` does not match the reference for long prefill even with FP32 promotion. Lock down a failing production-shape synthetic multi-token recurrence before switching kernels; require the unchanged full-checkpoint oracles to pass on both schedules. Keep only a correct alternate path for shapes not served by the custom kernel.
- [ ] Write a block-level failing test in `internal/models/qwen3_5/internal/delta/delta_test.go`: compare one-shot prefill against split prefill and repeated decode with nontrivial deterministic parameters, including both rolling caches and scope transfer. Port projection → rolling depthwise convolution plus SiLU → Q/K normalization → fused recurrence → gated RMSNorm → output projection. Preserve the MLX convolution tail as a contiguous slice; release old state after new graph nodes own the dependency. The public seam to the parent model is:

  ```go
  type Config struct {
      HiddenSize, KeyHeads, ValueHeads, KeyDim, ValueDim, KernelSize int
      Eps float32
  }
  type State struct { /* owned tail and FP32 recurrence */ }
  func Load(l *nn.Loader, prefix string, cfg Config, conv, aLog, dtBias *mlx.Array) *Layer
  func (l *Layer) Forward(x *mlx.Array, state *State) *mlx.Array
  func (s *State) Arrays() []*mlx.Array
  func (s *State) Free()
  ```

  `Load` consumes projections/norm via `nn.Loader` at `<prefix>.*`. The parent supplies shape-checked `conv1d.weight`, `A_log`, `dt_bias`; it owns parameter handles. `Forward` receives `[1,L,HiddenSize]`, accepts nil state for a whole sequence, and no mask (one unpadded sequence). A non-nil `State` starts empty and is updated in place; arrays are retained by the enclosing model runner. Run `go test ./internal/models/qwen3_5/internal/delta -count=1 -v` and record GREEN.

## B. Output-gated full attention

- [ ] Add tiny deterministic Python-derived references for grouped heads with a per-head query/gate split, partial RoPE, and cached causal suffix. Test both whole sequence and a prefilled branch where a multi-token suffix cannot see its future. Run `go test ./internal/models/qwen3_5/internal/attention -count=1 -v` for RED, implement with `nn.Loader` and the existing fused SDPA, then record GREEN.
- [ ] The seam is `type Config struct { HiddenSize, Heads, KVHeads, HeadDim, RotaryDims int; Theta, Eps float32; Bias bool }`, `func Load(l *nn.Loader, prefix string, cfg Config) *Layer`, `func (l *Layer) Forward(x *mlx.Array, state *cache.KVCache) *mlx.Array`. `state=nil` means no previous tokens. Follow Python `Qwen3NextAttention`: reshape Q projection per head before splitting query and gate; RMSNorm Q and K; use nontraditional partial RoPE and past offset; apply causal SDPA when L > 1 and no future keys when L == 1; multiply attended values by `sigmoid(gate)` before output projection. Prove behavior against an oracle that fails if the gate is dropped or future positions are allowed.

## Observed baseline

- Existing `internal/models`, `internal/generate`, `internal/chattemplate`, and `cmd/mlx-lm-go` tests passed before implementation.
- The real-binary CLI and HTTP acceptance tests both ran and failed before implementation: Qwen3.8 rejects `filter "default"` during template load; Qwen3.5 loads its template and rejects the unregistered `qwen3_5` architecture. Neither test skipped.
- Controlled Python substitution confirmed the large-prefill drift: Python's packed and unpacked recurrence paths both produced the same pinned Qwen3.8 golden, but swapping only the recurrence for the FP32-promoted built-in reproduced Go's wrong logit for token 90700 (`13.625` instead of `14.5625`). All recorded greedy IDs still matched; this is not sufficient to waive the numerical gate.
